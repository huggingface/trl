# C-GRPO

C-GRPO (Conformal Group Relative Policy Optimization) replaces GRPO's fixed group size with a per-prompt sampling budget chosen by split-conformal prediction. GRPO draws the same `num_generations` completions for every prompt, which wastes compute on prompts the policy already answers consistently. C-GRPO samples each prompt in increments along a budget grid (by default `2, 4, 8, 16, 32`) and stops as soon as the conformal prediction set over the completions drawn so far is a singleton.

One threshold per budget is fitted on a held-out calibration set with the current policy, before the first step and every `recalibrate_every` steps. By default the miscoverage level is set from the policy's own solve rate at the largest budget, so a weak policy does not end up with thresholds pinned at 1.0 and no early stopping.

To use C-GRPO, use the [`experimental.cgrpo.CGRPOTrainer`] class in `trl.experimental.cgrpo`.

## Usage

For tasks with a comparable final answer, pass an `answer_extractor` and a calibration dataset with a reference answer column:

```python
import re

from datasets import load_dataset
from trl.experimental.cgrpo import CGRPOConfig, CGRPOTrainer


def extract_answer(text):
    match = re.search(r"####\s*(-?[\d,\.]+)", text)
    return match.group(1).replace(",", "") if match else None


def correctness_reward(completions, answer, **kwargs):
    return [float(extract_answer(c) == a) for c, a in zip(completions, answer)]


def to_prompt(example):
    return {
        "prompt": example["question"] + "\nEnd with '#### <answer>'.",
        "answer": example["answer"].split("####")[-1].strip().replace(",", ""),
    }


data = load_dataset("openai/gsm8k", "main", split="train").map(to_prompt)
split = data.train_test_split(test_size=200, seed=0)  # calibration examples must not be trained on

trainer = CGRPOTrainer(
    model="Qwen/Qwen2.5-0.5B-Instruct",
    reward_funcs=correctness_reward,
    args=CGRPOConfig(budget_grid=[2, 4, 8, 16, 32], recalibrate_every=50, per_device_train_batch_size=32),
    train_dataset=split["train"],
    calibration_dataset=split["test"],
    answer_extractor=extract_answer,
)
trainer.train()
```

For execution-verified tasks such as code, set `score="first_success"` and pass a `verifier` instead. It is called as `verifier(completions=list_of_texts, **example)` with the calibration or training example's non-prompt columns and returns one boolean per completion.

## How it fits into GRPO

`num_generations` is the group *width* and equals `max(budget_grid)`. A prompt that stops at a smaller budget is padded up to that width with single-token completions. Padded rows get a NaN reward, so the group mean and standard deviation are computed over real completions only and their advantage is zero, and their tokens are removed from the loss mask and the loss normalizer. The savings come from generation: the policy only ever generates the completions that are kept.

The trainer logs:

- `cgrpo/mean_k`: average completions generated per prompt.
- `cgrpo/rollout_savings`: `1 - mean_k / max(budget_grid)`.
- `cgrpo/delta`, `cgrpo/qhat_{k}`, `cgrpo/calibration_solve_rate`: the fitted calibration.
- `cgrpo/calibration_rollouts`: completions generated by each calibration, which are not included in `rollout_savings`.

Two caveats:

- Calibration is not free. Each calibration generates `num_calibration_samples * max(budget_grid)` completions. Whether C-GRPO saves compute overall depends on that cost relative to the training rollouts saved between calibrations.
- By default `delta` is chosen from the same calibration scores that produce the thresholds, which uses the data twice. Set `split_delta=True` to choose them on disjoint halves, which restores split-conformal exactness at half the effective calibration size.

## vLLM

C-GRPO works with `use_vllm=True` in both `vllm_mode="server"` and `vllm_mode="colocate"`. Each budget increment is a separate generation request for the prompts still being sampled, so a training batch costs at most `len(budget_grid)` requests. Padded rows are given a NaN sampling logprob, so `vllm_importance_sampling_correction` leaves them uncorrected (ratio 1) instead of applying a spurious ratio.

## Limitations

The current implementation supports single-process training. Multi-process training, tool calling, environments, `rollout_func` and vision-language models raise `NotImplementedError`. Padded rows appear in the logged completion-length statistics and completion tables as one-token completions.
