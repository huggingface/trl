## Checking that fla is actually used (copy this into your lib's checks)

Qwen3.5 hybrids run a pure-torch gated delta rule about 20x slower when `flash-linear-attention` doesn't import, and nothing warns. transformers (>= 5.15) binds the kernel once, at import of `modeling_qwen3_5`, inside a `try/except Exception`. Two traps: installing `flash-linear-attention` with `--no-deps` leaves out `fla-core`, so `import fla` fails; and `transformers.utils.import_utils.is_flash_linear_attention_available()` still returns True in that state, because it only checks that the package looks installed. Check the binding itself, in the venv the trainer runs in:

```python
import importlib
from transformers.integrations.hub_kernels import resolve_internal_import

fn = resolve_internal_import(importlib.import_module("fla"), "ops.gated_delta_rule.chunk_gated_delta_rule")
print(f"{fn.__module__}.{fn.__name__}")  # want: fla.ops.gated_delta_rule.chunk.chunk_gated_delta_rule
import causal_conv1d; print(causal_conv1d.causal_conv1d_fn.__module__)  # want: causal_conv1d.causal_conv1d_interface
```

And at run time, in the training process after the model is built (this is what the model actually calls):

```python
import sys, inspect
mod = sys.modules[type(model).__module__]  # e.g. transformers.models.qwen3_5.modeling_qwen3_5
for name in ("torch_chunk_gated_delta_rule", "causal_conv1d_fn"):
    print(name, inspect.getclosurevars(getattr(mod, name)).nonlocals.get("implementation"))
```

`envs/trl/install.sh` runs the first check and fails the install if fla doesn't bind.

TRL-specific: AsyncGRPO's tree packing replaces both functions with its own (`trl/experimental/async_grpo/packing.py` `patch_tree_gdn`): the delta rule goes through TRL's vendored Triton tree kernel (`tree_gated_delta_rule.py`, derived from fla), so it doesn't depend on fla at train time, while the short convolution still calls whatever `causal_conv1d_fn` transformers bound (the `causal_conv1d` package or the slow torch fallback). So for TRL the binding that matters most at train time is `causal_conv1d`; for libraries without their own kernel, it's fla.

## Proposed changes to SHARED_W1

1. **Allow token-sized steps, with the rollout count recorded.** TRL's optimizer step is `gradient_accumulation_steps` packed micro-batches of `token_budget` tokens per rank, not a number of groups; there's no config that makes it "the next 32 complete groups". Proposal: for token-batched libraries, size the step to ~256 rollouts at the start of training and report `num_rollouts` per step (TRL logs it as `batch/samples_per_step`), so reward-vs-samples plots stay comparable.
2. **Zero-advantage groups: accept "dropped" as a recorded library behaviour.** TRL always drops all-equal-reward groups (no switch), which with token-sized steps amounts to refill. On this workload ~30-50% of groups are zero-std at the base policy (probe items 20 and 23), so TRL consumes 1.5-2x more prompts per step than a lib that keeps them. Plots against prompts consumed should note it; reward-vs-wall-clock is unaffected.
3. **Make `enable_thinking` and the generation-config handling explicit for every engine.** The Qwen3.5 template default is non-thinking, but vLLM's chat endpoint and libraries that render with their own template can differ; each lib should log the rendered tail of one prompt (as in NOTES item 20) in its smoke test. Also pass `--generation-config vllm` (or the engine's equivalent) so the model card's top_p/top_k defaults don't leak into "top_p 1.0".
4. **Expect ~25% truncation at 16384 at step 0, mostly loops** (item 23), and report `truncated_fraction` per step: a falling curve is part of the learning signal, not a config bug.
