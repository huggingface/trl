# SkyRL notes

## Research (2026-11-09)

Source: https://github.com/NovaSky-AI/SkyRL, pinned to main `d87004689e3a57e4041991a3c4cf71bed333a44d` (2026-11-06). The latest tag `skyrl-v0.4.0` (2026-10-01) is 136 commits behind and still ships vLLM 0.30.0 and an unpinned `flash-linear-attention`; main pins `flash-linear-attention==0.6.0` with the comment that 0.5.2 + Triton 3.7.1 corrupts GDN outputs in ~40% of calls on B200 (triton-lang/triton#10590). That alone decides for main on b200. The repo layout changed: `skyrl-train/` is now a stub, everything lives in the `skyrl` package (`skyrl/train`, `skyrl/backends/skyrl_train`), examples in `examples/train*/`.

### Install

- Recommended: their Docker image `novaskyai/skyrl-train-ray-2.57.0-py3.12-cu13.0`. Without Docker (what we do): CUDA 13 driver, `uv venv --python 3.12 <venv outside the repo>`, `uv sync --active --extra fsdp`, Ray 2.57.0, `libnuma` on the node. The docs also tell you to set `RAY_RUNTIME_ENV_HOOK=ray._private.runtime_env.uv_runtime_env_hook.hook` and launch with `uv run --isolated --extra fsdp`, which re-resolves an isolated env per run and per Ray worker. We skip that: one locked venv, workers inherit the driver interpreter (`install.sh`, `launch/skyrl/common.sh`).
- Backend extras `fsdp`, `megatron`, `jax` are mutually exclusive. `fsdp` pins torch 2.13.0 (cu130), vLLM 0.33.0 (held below vLLM's own torch 2.14 pin by an override), flash-attn 2.8.3, flashinfer 0.7.2.post1, `flash-linear-attention==0.6.0`, `causal-conv1d==1.6.2.post1`, transformers `>=5.6.1,<=5.16.1`, ray 2.57.0. So fla and causal-conv1d come with the default FSDP install; nothing extra to add.

### Training backend, inference engine

- Trainer: `trainer.strategy=fsdp` (default; PyTorch `fully_shard`, i.e. FSDP2) or `megatron` (Megatron-Bridge + TE 2.19). Full-FT policy weights are loaded in fp32 and trained with FSDP2 mixed precision (bf16 params, fp32 reduce): master dtype fp32.
- Inference: vLLM 0.33.0 (default `generator.inference_engine.backend=vllm`), engines as Ray actors behind SkyRL's HTTP servers and a `vllm-router` data-plane router. Weight sync over NCCL by default.
- Qwen3.5 docs (`docs/content/docs/models/qwen.mdx`): "Supported on main with the Megatron backend. Dense models also work with FSDP". The FSDP example `examples/train/models/run_qwen3.5_0.8b.sh` sets `language_model_only=true` (trainer, ref and vLLM) and `trainer.remove_microbatch_padding=false` with the comment "sample packing is not yet supported for Qwen3.5 with FSDP backend" (transformers#44910). On Megatron, `language_model_only=true` routes Qwen3.5 to a native GPTModel + GDN THD packing path; on Blackwell they say to export `FLA_TILELANG=0` (TileLang packed backward aborts).

### Async / off-policy modes

1. Synchronous colocated (`trainer.placement.colocate_all=true`): the default in almost every example script, including all math recipes except the explicitly async ones.
2. One-step off-policy (`examples/train/async/`, custom `AsyncRayPPOTrainer`): split GPUs, trainer always one step behind.
3. Fully async (`trainer.fully_async.enabled=true`, `FullyAsyncRayPPOTrainer`, `examples/train/fully_async/`): PipelineRL/AReaL style in-flight weight updates with pause/sync/resume of generation, staleness bounded by an AReaL-style capacity rule `accepted + running <= (S + step) * B`. Config default `max_staleness_steps=4`, `num_parallel_generation_workers=768`, `clear_kv_cache_on_weight_sync=false`. Requires `train_batch_size == policy_mini_batch_size`, `generator.batched=false`, no dynamic sampling, and a `/chat/completions` generator (the default SkyRL-Gym generator in non-batched mode qualifies). Their fully-async recipes pair it with `policy_loss_type=rollout_is` (GLM-5 IcePop-style) plus a geometric sequence mask 0.99-1.01.
- What they recommend for a split trainer/inference setup like ours: fully async. The docs present it as the answer to stragglers, and their DAPO async recipe (`run_dapo_qwen3_1.7b_aime_fully_async.sh`, 4 train + 4 inference GPUs, Qwen3-1.7B-Base) uses `max_staleness_steps=8`, 144 generation workers, mini-batch 32. The GSM8K fully-async example uses staleness 4 and `B*(S+1)` workers. We use the library default staleness 4 for W1 (and record it).

### Defaults changed on main (2026-11-05, #2635)

`policy_loss_type` regular -> `dppo`, `loss_reduction` token_mean -> `prompt_mean`, `grpo_norm_by_std` True -> False. Also on main: `use_kl_loss=true` by default (coef 0.001, k3), AdamW `weight_decay=0.01`, `scheduler=constant_with_warmup` with 0 warmup, `remove_microbatch_padding=true`, `logprobs=1` from vLLM. Published recipes predate these and set most of them explicitly.

### Math recipes and published numbers

- GSM8K (`examples/train/gsm8k/run_gsm8k.sh`): Qwen2.5-1.5B-Instruct, FSDP, 4 GPUs colocated, 1024 prompts x 5 samples, mini-batch 256 (4 optimizer steps per batch), lr 1e-6, KL loss on, 1024 max gen. Published (`docs/content/docs/recipes/overview.mdx`): eval accuracy 0.796 after 140 steps on 4xH100 at commit a95b699, WandB `sky-posttraining-uc-berkeley/gsm8k_recipes`.
- DAPO (`examples/train/algorithms/dapo/`): published peak AIME24 for Qwen2.5-Math-7B (pass@32 0.633, avg -0.304 on the +-1 scale, 320 steps), Qwen3-1.7B (0.4 / -0.702, 225 steps), Qwen3-4B (0.6 / -0.51, 90 steps), all on 8xH100 at commit 8263149, WandB report `ijmo1v6q`. 8k response length; far beyond the 3 node-hour budget, so not reproduced.
- Qwen3.5: `run_megatron_dapo_qwen3.5_9b.sh` (DAPO, 1x8 H100, TP=4, packing off), `run_qwen3.5_0.8b.sh` (GSM8K, FSDP). No published curves for Qwen3.5.

### Harbor (W2)

- Lives in `examples/train_integrations/harbor/` (there is no `examples/terminal_bench` any more): `HarborGenerator` (implements `GeneratorInterface`), `HarborTaskDataset` (a dataset of Harbor task dirs), entrypoints `main_harbor.py` and `main_harbor_fully_async.py`, trial config template `harbor_trial_config/default.yaml`, run scripts for CodeContests (sync and fully async, Qwen3-8B). Also `harbor_skycap/` (token-exact capture) and `thunder_agent/`.
- Harbor runs in-process: `Trial(TrialConfig).run()` per trajectory, agent `terminus-2` by default, calling SkyRL's vLLM router through LiteLLM (`hosted_vllm/<served_model_name>`), with `collect_rollout_details: true` so token ids and logprobs come back from Harbor. Not through OpenEnv.
- Harbor version: the `harbor` extra is `harbor[daytona,modal]` pinned in `uv.lock` to git rev `3de07a0e` (v0.13.1+25, 2026-06-09). Sandbox providers at that rev: daytona (the default in `default.yaml`), docker, modal, e2b, runloop, gke, plus apple_container, cwsandbox, islo, langsmith, novita, singularity, tensorlake, use_computer, wandb. No `hf-sandbox`: it was added in Harbor v0.21.0 (#1925, 2026-08-04); current Harbor main is 0.25.0.
- Using HF Sandboxes therefore needs (a) overriding the Harbor pin to >= v0.21.0 (the `Trial` / `TrialConfig` / `agent_result.rollout_details` / `RolloutDetail` names SkyRL imports still exist on Harbor main), (b) `environment.type: hf-sandbox` in the trial config, HF token in env, and (c) the known `tar --no-same-owner` fix: on Harbor main, `HFSandboxEnvironment.upload_dir` still calls `remote_unpack_command(...)` without `no_same_owner=True` (the helper has the flag, hf_sandbox doesn't pass it), so that is a one-line Harbor patch. Not tested yet; W2 phase.
- Failure handling worth knowing for W2 fairness: any failed or timed-out trajectory zeroes the loss mask of its whole group; context-length-exceeded gets reward 0 (trained on unless `apply_overlong_filtering=true`).

## Proposed changes to SHARED_W1

1. **Define the clip reference policy.** "clip eps low 0.2 / high 0.28" doesn't say what the ratio's denominator is. In an async library it can only sensibly be the sampler's (rollout) logprobs: SkyRL's fully async mode forbids recomputing pi_old, and with one optimizer step per batch a recomputed pi_old makes the ratio 1, so the clip is a no-op. Proposal: "ratio = pi_theta / pi_sampler (the logprobs returned by the inference engine), clipped or masked to (0.8, 1.28); state whether the library clips one-sided (PPO) or masks two-sided (IcePop/rollout_is)". SkyRL uses the two-sided mask.
2. **Make packing correctness part of the hybrid check, not just speed.** On FSDP, SkyRL's default sample packing silently corrupts Qwen3.5 logprobs: up to 2.4 nats on the second packed sample, because the GDN state leaks across the boundary. Every library that packs hybrids should report the packed-vs-alone logprob test (SkyRL's numbers are in item 15), and libraries should run with packing off where it leaks, recording the throughput cost.

1. **Separate venv `bench-skyrl-w2`** (05:55, `envs/skyrl/install_w2.sh`, hopper-cpu job 365021): `uv sync --frozen --extra fsdp` from the same lock as bench-skyrl, then `harbor[hf-sandbox]==0.25.0` from PyPI (the TRL side's Harbor) with the training stack held by constraints, then the tar patch. SkyRL's own `harbor` extra pins git `3de07a0e` (v0.13.1+25), which has no hf-sandbox (added in v0.21.0). Every Harbor name SkyRL's `HarborGenerator` imports (`RolloutDetail`, `TrialConfig`, `Trial.create`) still exists on 0.25.0; the install's import check covers them plus `main_harbor_fully_async`.
2. **SkyRL's Harbor defaults don't fit W2** (06:10): `harbor_trial_config/default.yaml` is Daytona with `override_cpus=1`, 1 GB memory / storage overrides, a Daytona-only env kwarg, 32 turns and a 1200 s agent timeout, and SkyRL's entrypoint deep-merges CLI overrides into it, so keys can't be removed. Our entrypoint (`launch/skyrl/skyrl_w2_main.py`) builds the trial config from `configs/skyrl/w2-M.harbor.yaml` alone: hf-sandbox with no overrides, terminus-2 with 600 s / 30 calls / 8192 output tokens / 65,536 context / summarisation off, thinking off per request (`chat_template_kwargs`).
3. **Stock SkyRL would zero almost every W2 group** (06:15, from the code): `HarborGenerator._harbor_agent_loop` treats `AgentTimeoutError` as a failure (no retry, loss mask 0), and `build_step_wise_generator_output` then masks the whole group of any failed trajectory. The probe had 226 of 452 episodes hit the 600 s budget, so a group of 8 has no timeout ~1% of the time. Harbor 0.25 still runs the verifier after an agent timeout (`SingleStepTrial` catches it) and terminus-2 fills `rollout_details` in a `finally`, so `skyrl_w2_main.py` scores those episodes as SHARED_W2 asks; the rest of SkyRL's failure handling is untouched (retry once on a missing verifier result, group zeroing for unscored episodes, reward 0 on context overflow, since Harbor doesn't verify after `ContextLengthExceededError`).
4. **`remove_microbatch_padding=false` pads every micro-batch to the step's global width** (06:20, from the code): `SampleBasedBatchIterator` uses `TensorBatch.chunk`, which slices rows but keeps the batch-wide padded width (max prompt + max response over the whole step), and the model forward only drops padding when `remove_microbatch_padding=true`.
