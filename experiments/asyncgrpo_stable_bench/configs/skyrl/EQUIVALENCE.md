## Recommended arm (`w1-S-recommended.overrides`)

Same model, data, prompt, reward, 4+4 split, lengths, sampling, optimizer, steps, checkpoints and seed as the shared arm. These are the only differences:

| knob | shared | recommended | why |
|---|---|---|---|
| `trainer.algorithm.policy_loss_type` | `rollout_is` (ratio band 0.2/0.28 against the sampler) | `dppo` (code default since #2635) | DPPO, "Rethinking the Trust Region in LLM RL": a binary total-variation trust region on the absolute probability difference against the **rollout** logprobs (`delta_low=delta_high=0.2`). Because it anchors on the rollout logprobs, the trainer skips the old-logprob forward pass, and the update is bounded against the actual sampling policy, staleness included. |
| `trainer.algorithm.loss_reduction` | `token_mean` | `prompt_mean` (code default since #2635) | Token mean inside each prompt's group, then mean over the 32 prompts: every prompt weighs the same regardless of response length. |
| `eps_clip_low/high` | 0.2 / 0.28 | unused by DPPO (its band is `dppo.delta_low/high` = 0.2/0.2 on the probability difference) | |

Unchanged from the shared arm, because they already are SkyRL's recommended values: group-mean advantage without std (`grpo_norm_by_std=false` is the code default), fully async with `max_staleness_steps=4` (code default), no zero-variance filtering or refill (code default), no off-policy correction. KL stays off: the config default is still `use_kl_loss=true` (coef 0.001), but every SkyRL math and async recipe (DAPO, fully async GSM8K, fully async DAPO) sets it to false, so we read that as the recommendation. Weight decay stays at the shared 0.0 rather than the code default 0.01, since optimizer settings are part of "everything else shared". SkyRL's fully-async recipe scripts use `policy_loss_type=rollout_is` with a geometric sequence mask rather than DPPO. They predate the #2635 default change, so we follow the code default; `rollout_is` is the alternative if main prefers recipe scripts over code defaults.

## Hybrid model specifics

- Sample packing (`trainer.remove_microbatch_padding`) is off: on the FSDP path SkyRL packs a micro-batch into one row and passes only `position_ids` to the HF model; transformers' Qwen3.5 gated-DeltaNet layers only respect sequence boundaries when `cu_seq_lens_q` is passed, so packed samples would leak recurrent state into each other (measured in `envs/skyrl/NOTES.md`). SkyRL's own Qwen3.5 FSDP example turns packing off for this reason. Micro-batches therefore hold one sequence each (`micro_train_batch_size_per_gpu=1`), so nothing is packed. **Correction (2026-11-10):** they are still padded: with `remove_microbatch_padding=false`, `TensorBatch.chunk` never trims, so every sequence is forwarded at the step's max prompt + max response width (~62% of forwarded tokens are padding in the W1 runs; `results/tables/throughput_fair.md`).
- fla (`flash-linear-attention==0.6.0` + `fla-core`) and `causal-conv1d==1.6.2.post1` are part of SkyRL's `fsdp` extra; the binding is checked in `envs/skyrl/NOTES.md`.

## Gaps

PPO-clip was approximated by `rollout_is` (two-sided token mask instead of a one-sided clip), because SkyRL's fully async mode forbids losses that recompute old logprobs. Noted under "Proposed changes to SHARED_W1" in `envs/skyrl/NOTES.md`.
- Prompt order differs (SkyRL reshuffles with its own seed).
- Micro-batches are padded rather than packed, which costs trainer throughput on Qwen3.5; it does not change the math.
