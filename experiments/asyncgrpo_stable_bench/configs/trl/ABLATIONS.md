# TRL leave-one-out arms: knobs on main

TRL main @5623e8b63. Each arm of the ablation ladder mapped to what turns it off. The base for the ladder should be TRL's own defaults (score centering on, std-normalized advantages), which differ from the shared W1 config in `w1-S.py` (clipped GRPO, mean-only advantages); `ABLATION=` in `w1-S.py` flips the switches listed below.

| arm | on (default) | off | clean? |
|---|---|---|---|
| adaptive concurrency | `max_concurrent_rollouts=None` -> `max_staleness * samples_per_step`, used as a **ceiling**; the rollout loop starts at `min(ceiling, kv_cache_tokens // max_model_len)` and every 5 s cuts the cap 30% when vLLM KV usage > 0.8 and grows it 25% when usage < 0.6 with an empty queue (`async_rollout_worker.py` `_init_concurrency_cap`, `_control_loop`) | `ABLATION=fixed_concurrency MAX_CONCURRENT=<n>`: a `loop_cls` subclass turns both methods into no-ops, so the cap stays at `n` | **No.** There's no config switch: the controller always runs, and setting `max_concurrent_rollouts` only moves its ceiling. The off arm overrides two private methods. Proposed: a public `adaptive_concurrency: bool` (or document `max_concurrent_rollouts` as "fixed cap" and the controller as opt-in). |
| token-budget packing | `token_budget` (default = vLLM `max_model_len`, 18432 here; shared run uses 49152): samples packed into one row per rank up to the budget in unique tokens | none | **No.** `TokenBudgetBatcher` is the only batching path (`get_train_dataloader`); there is no unpacked/padded mode. The closest arm is `TOKEN_BUDGET=` (empty: the trainer default, 18432, about one long sample per row) vs the tuned budget, with `GRAD_ACCUM` raised to keep tokens per step equal. That measures "budget size", not "packing on/off". |
| tree / forking attention | always: `attn_implementation="tree_fa3"` and `patch_tree_gdn` for the gated DeltaNet layers (`async_grpo_trainer.py` ~L970-1010) | none | **No, drop the arm.** Tree packing is hard-wired. For hybrids it is also the only correct packed path: without it the linear-attention layers would scan across the samples of a row. A "no prefix sharing" variant would need a source change (e.g. give every sample its own root). |
| zero-advantage group filtering | always: a group with all-equal rewards is dropped (`_score_group`, ~L1399) | none | **No.** Hard-coded in a private method. Turning it off means overriding `_score_group` (~100 lines) in a `loop_cls`. With mean-centred advantages the dropped samples carry zero gradient, so the arm only measures compute spent on them and the token-denominator change, not a learning-signal change. Proposed: a public `drop_zero_std_groups: bool`. |
| score centering | `score_centering=True` (trainer default) | `score_centering=False` (clipped objective with `epsilon`/`epsilon_high`) | **Yes.** One flag. The shared W1 run has it off; `ABLATION=score_centering` turns it on. Needs `num_sampler_logprobs>=1` (default 8) and costs vLLM top-8 logprob serialisation (see the vLLM logprob notes). |
| LoRA vs full FT | full FT | `peft_config=LoraConfig(r=..., target_modules=...)`; vLLM `--enable-lora --max-lora-rank <r> --max-loras >= max_staleness + 2` and `VLLM_ALLOW_RUNTIME_LORA_UPDATING=1` | **Yes, with a caveat.** Adapter-only weight sync (the "sync size" part of the arm) needs vLLM `--data-parallel-size 1`; with DP=4 the trainer falls back to merged full-weight sync with a warning (`select_adapter_sync`). So on 4 inference GPUs the LoRA arm either keeps DP=4 (memory saving only, same sync size) or runs one engine with TP=4 / fewer inference GPUs. LR must be retuned (1e-5 was used on the sanity bed). Not wired into `w1-S.py` yet. |

Also switchable, not in the PLAN list: `ABLATION=std_adv` restores TRL's default `(r - mean) / (std + 1e-8)` advantages.
